# Working on MIDI Memory

## Git

**Do not stage or commit anything unless asked.** Make the changes, say what you
changed, and leave the working tree dirty. Lakin decides when something is a commit
and will ask for one. This includes `git add` — leave staging alone too.

When a commit *is* asked for: commit directly to `main` rather than branching per
change. Pushing is Lakin's to run; the agent shell cannot authenticate to GitHub.

## Layout

Three packages under `midi_memory/`, and the layering is enforced by convention:

- `shared/` — the MIDI event model, SMF read/write, the password cookie, and
  `protocol.py`, which is the whole contract between the two halves. It imports
  neither of the others.
- `server/` — the library, its web UI, the client registry and the ingest endpoint.
  Never imports `client/`.
- `client/` — the recorder, the MIDI backends, the spool and the uploader.

`tests/` mirrors that split. The uploader tests run a real client against the real
server app over httpx's ASGI transport, so the join between the halves is covered
with only the socket replaced.

## Conventions

- The version lives in `midi_memory/__init__.py` and nowhere else. `pyproject.toml`,
  both FastAPI apps and both UI footers derive from it.
- `brand/icon.svg` is the artwork; everything under `midi_memory/*/static/brand/` is
  generated by `scripts/render_icons.sh` and should not be hand-edited.
- Comments explain *why*, not what. The existing code sets the tone — match it.

## Verifying

- `.venv/bin/python -m pytest` for the suite.
- Run the two halves against each other for anything touching the UI or the upload
  path; `.env.server` and `.env.client` hold the dev config, and the client's
  `MIDI_MEMORY_MIDI_SOURCE=mock` plays itself.
- A running process does not pick up Python or template changes — restart it. This
  has caused false "the fix didn't work" readings more than once.
- `localhost` is a secure context but a LAN address is not, so browser APIs gated on
  that (clipboard, and others) appear to work in local testing and fail on the real
  deployment.
